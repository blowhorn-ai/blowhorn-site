Connect an AI assistant over MCP

Point Claude, ChatGPT, Codex, Cursor, VS Code, Windsurf, Gemini CLI, Zed, Cline, Goose, Muse, Grok, Grok Bot, or Arcade at https://mcp.blowhorn.ai/mcp.

Connect an MCP client to Blowhorn's hosted MCP server at https://mcp.blowhorn.ai/mcp. The server is Streamable HTTP. It serves seven read-only tools: listContentItems, getContentItem, getEvents, getConnections, listSchedules, getScheduleById and getPlatformSessions. It does not post, schedule, or change anything, and it serves tools only: no prompts, resources, or sampling. Where a tool needs an organization, pass it as the organizationId argument.

Sign in with OAuth when the client can. A client that supports MCP OAuth 2.1 needs only the URL. Dynamic client registration and PKCE are on. The resource is https://mcp.blowhorn.ai/mcp. The authorization server is the one advertised in https://mcp.blowhorn.ai/.well-known/oauth-protected-resource. A client that cannot finish that sign-in sends a Blowhorn API token as Authorization: Bearer <token>. Create the token in Get a Blowhorn API token. Put no other secret in a client config.

What the hosted server is, and how it relates to the desktop app's own process, is in the MCP server reference. New to this? Follow Connect an assistant and read your queue first.

Grok Bot

Blowhorn is not in Grok Bot's connector catalog yet. Add it as a custom MCP server. Grok Bot runs in the cloud, so it cannot start Blowhorn's local server on your Mac. It connects to the hosted server at https://mcp.blowhorn.ai/mcp. No token or header is needed for the add step: you sign in with OAuth.

The hosted server is read-only. It has the seven tools named at the top of this page, so your bot can read your queue, a post, your activity, your connections, where your social accounts are signed in and your schedules. It cannot post, schedule or change anything. To post, use the CLI or blowhorn-axi on the Mac where Blowhorn runs, or the desktop app's own process described in the MCP server reference.

  1. In a chat with your bot, ask it to add a custom MCP server. Say "custom" so the bot does not look in the catalog:

    Add a custom MCP server named blowhorn at https://mcp.blowhorn.ai/mcp.

  2. The bot shows the name and the URL and asks you to confirm. Check that the URL is exactly https://mcp.blowhorn.ai/mcp, then confirm.

  3. The bot shows a connect card. Open it. You land on the Blowhorn sign-in page at cloud.blowhorn.ai. Sign in, or create a new Blowhorn account there. Approve access.

  4. Back in the chat, check it in your next message. Ask:

    Which Blowhorn tools do you have? Then list my Blowhorn connections.

    The bot should list the seven read-only tools above and answer from getConnections. Where a tool needs an organization, it is passed as the organizationId argument.

If a client cannot finish OAuth, send a Blowhorn API token as Authorization: Bearer <token> instead. The steps are in Get a Blowhorn API token.

If the bot reports 401 Unauthorized when it connects, the OAuth sign-in did not finish, or a Bearer header is missing or malformed. Sign in again, or use the header Authorization: Bearer <token> with a current token. If it connects but a tool call fails with a 401, the sign-in expired or the token was revoked: sign in again, or get a new token and update the header. If you connected before 20 November 2026, sign in once more: the sign-in address changed, so the client registers again and completes sign-in once. If you opened the URL in a browser and saw a JSON error, that is expected: see Opening the gateway URL in a browser.

Arcade

Arcade connects to the hosted server. Do not create a new Arcade server or deploy one. Register the existing hosted server as a Remote MCP.

  1. Open the Arcade servers dashboard.
  2. Choose Add Server, then Remote MCP.
  3. Set the ID to blowhorn and the URI to https://mcp.blowhorn.ai/mcp.
  4. Under Advanced settings, choose OAuth2 authorization. Leave Client ID, Client Secret, Authorization URL, and Token URL empty so Arcade can use dynamic client registration. That is the same pattern as Arcade's Atlassian remote MCP guide.
  5. Save, then complete the Blowhorn OAuth sign-in.
  6. Pick the tools in an MCP Gateway.

The tools are the seven read-only tools named at the top of this page. This is a connection in your Arcade account. Blowhorn is not listed in Arcade's public catalog.

Authentication

Get a Blowhorn API token

Use this when the client cannot finish OAuth. The Blowhorn desktop app has no screen for creating a token. Create it on your Blowhorn account's web page:

  1. Open cloud.blowhorn.ai/security/tokens and sign in with your Blowhorn account. This is the Tokens tab under Security.
  2. Click Create.
  3. Enter a Token Name that says where the token is used, such as grok-bot-mcp, and a Token Purpose, then click Create. The new token appears in the list.
  4. In that token's row, click the Download icon. The download saves a file named token_<id>.json.
  5. Open the file. The value of its "token" field is the API token. Give a client that value, and nothing else, where it asks for the Bearer token; the client sends it as Authorization: Bearer <token>.

Make one token per client, so you can revoke one without breaking the others, and delete the downloaded file once the token is in the client. To stop using a token, delete it from the same page with the Delete icon in its row, or see Revoke a leaked token.

Opening the gateway URL in a browser

To check from a browser that the server is up, open mcp.blowhorn.ai/healthz instead, which answers {"ok":true,...}. To check your token, connect a client and ask it which Blowhorn tools it has.

Revoke a leaked token

If an API token for your Blowhorn account leaks, revoke it at once. Having the token is enough; no sign-in is needed:

A 200 response means the token no longer works, if it existed. A 200 does not confirm the token existed. A 503 response means nothing was revoked, so run the call again.

While you are still signed in with a token you trust, you can delete the token by ID instead. List your tokens with GET https://cloud.blowhorn.ai/api/identity/tokens, then send DELETE https://cloud.blowhorn.ai/api/identity/tokens?tokenId=<id> with Authorization: Bearer <token>.

Example prompts

The server can read. Ask for a read, and read the result before you ask for another:

List my content items.

Show me one content item and tell me its status.

What events do you see, and which connections are set up?

A request to post, schedule, or change anything has no tool on this server. The assistant should say so.

Troubleshooting

  • The client shows no Blowhorn server. The URL must be exactly https://mcp.blowhorn.ai/mcp. Restart the client after saving the config. Claude Desktop only reads its config at startup.
  • The client reports 401. The OAuth sign-in did not finish, or the Bearer header is missing or malformed. Use the header Authorization: Bearer <token> with a current token, or sign in again. If you connected before 20 November 2026, sign in once more: the sign-in address changed, so the client registers again and completes sign-in once.
  • A tool call returns 401 after the client connected. The sign-in expired, or the token was revoked. Sign in again, or create a new token and update the header.
  • The tool list is not the seven read tools. The client is pointed at a different server. Set the URL to https://mcp.blowhorn.ai/mcp and remove any command that starts a local process.
  • A browser shows a JSON error at /mcp. That is expected. See Opening the gateway URL in a browser.

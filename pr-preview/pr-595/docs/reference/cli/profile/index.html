blowhorn profile accounts

List, map or unmap a profile's social accounts. An account is a Blowhorn connection on one platform; a profile acts through the accounts mapped to it, one per platform, whoever owns them, so a person may keep several profiles and a brand profile reaches the accounts mapped to it. --map replaces the profile's account on that platform; --unmap leaves the connection itself intact. --page records the account's own page on the account already mapped for that platform, which is where the profile's handle is read from: Chrome profile discovery finds a sign-in, never a LinkedIn /in/ name.

Argument Required Description
name yes Profile name
Flag Type Default Description
--map string Map this connection id to the profile, replacing its account on that platform
--unmap string Unmap this connection id from the profile; the connection is left intact
--page string Record this account page (x.com/<handle>, linkedin.com/in/<name>, github.com/<login>, reddit.com/user/<name> or bsky.app/profile/<handle>) on the account mapped for its platform
--json boolean false Emit machine-readable JSON output
--platform string Platform scope for blowhorn profile. One of: bluesky, linkedin, reddit, slack, x, all (all means every platform listed here)
--pace string Pace of the random delays between blowhorn profile accounts browser steps: a preset name (fast/normal/slow) or a numeric multiplier (e.g. 0.5, 2.0). Resolved as CLI flag, then BLOWHORN_PACE, then defaults.pace in .blowhorn.yaml (normal when none is set); an unrecognized value is rejected before anything runs
--risk-profile string Risk Profile this run uses: cautious, standard or brisk. For this one run it beats the schedule's value, the profile's choice and configuration. A value after the command word wins over one before it; an unrecognized value is rejected before anything runs

Also takes the shared flags: --config, --log-dir, --profile, --exclude, --headless, --chrome-launch, --headed, --dry-run, --verbose.

blowhorn profile auth

Refresh authentication/session state for one or more platforms.

Supported platforms and authentication mechanisms:

linkedin - Persistent browser session. Automated login via LI_USERNAME / LI_PASSWORD in the store, with fallback to manual browser entry.

x - Persistent browser session. Automated login via X_USERNAME / X_PASSWORD in the store, with fallback to manual browser entry.

reddit - Persistent browser session. Automated login via RDDT_USERNAME / RDDT_PASSWORD in the store, with fallback to manual browser entry.

slack - Hybrid: session credentials (xoxc token + d cookie) captured through the run's browser driver (the extension by default), saved to the profile's Slack credential in the store, and reused for direct API calls. No Slack app install required. Use --workspace <host> to capture a new workspace; omit it to refresh every workspace listed under slack_workspaces in that credential. Use --mode paste for the legacy OAuth-token flow.

bluesky - No browser. Logs in to Bluesky with a handle and app password -- the same login every post makes -- and stores the pair only when Bluesky accepts it, so a refused credential is never saved. For one named profile in a terminal it asks for both (the stored handle is the default; a blank app password keeps the stored one); --handle and --app-password-stdin supply them without a prompt. Otherwise the stored pair is logged in with and nothing is written.

Use --profile all to refresh every profile in your organization after applying any --exclude filters. The profiles are read from the store; a store that cannot be reached is the named cause and exit 3.

With --headless the browser still opens, as a background window (Chrome is never run headless); only automated credential login is attempted and the manual browser fallback is skipped.

Flag Type Default Description
--all boolean false Refresh every platform blowhorn profile auth can log in to (linkedin, x, reddit, slack). Supersedes --platform: when --all is set the platform is ignored, whether you typed it or inherited it from BLOWHORN_PLATFORM or defaults.platform
--json boolean false Emit machine-readable JSON output
--workspace string Slack only: capture session credentials for this workspace domain (e.g. mesheryio.slack.com). Opens a browser window; sign in to Slack, and the xoxc token + d cookie are extracted. If omitted, all workspaces listed under slack_workspaces in the profile's Slack credential in the store are refreshed.
--mode string Slack only: session (default) captures xoxc/d via browser; paste prompts for a User OAuth Token (xoxp-…) - requires app install.
--handle string Bluesky only, one named profile: the handle to log in as (alice.bsky.social; a leading @ is dropped). Stored with the app password only when Bluesky accepts the login; omit it to use the stored handle
--app-password-stdin boolean false Bluesky only, one named profile: read the app password from the first line of stdin, so it never reaches argv, the daily log or a prompt. A blank line is refused and nothing is written
--platform string Platform scope for blowhorn profile. One of: bluesky, linkedin, reddit, slack, x, all (all means every platform listed here)
--pace string Pace of the random delays between blowhorn profile auth browser steps: a preset name (fast/normal/slow) or a numeric multiplier (e.g. 0.5, 2.0). Resolved as CLI flag, then BLOWHORN_PACE, then defaults.pace in .blowhorn.yaml (normal when none is set); an unrecognized value is rejected before anything runs
--risk-profile string Risk Profile this run uses: cautious, standard or brisk. For this one run it beats the schedule's value, the profile's choice and configuration. A value after the command word wins over one before it; an unrecognized value is rejected before anything runs

Also takes the shared flags: --config, --log-dir, --profile, --exclude, --headless, --chrome-launch, --headed, --dry-run, --verbose.

blowhorn profile create

Create a profile in your organization on Blowhorn. It reads a JSON document on stdin (--payload-stdin) holding the fields a person sets: name (required), description and userId. userId is the organization member the profile represents, as blowhorn org members lists them; leave it out for a brand. Blowhorn adds the organization, and you own the profile. The name must be handle-shaped (lowercase letters, digits, - or _) and not one another profile uses. Any other key is refused, every refusal comes before anything is sent, and --dry-run makes the same checks and sends nothing. No folder is created and no email is looked up.

Flag Type Default Description
--payload-stdin boolean false Read the profile document (JSON: name, description, userId) from stdin; required
--json boolean false Emit machine-readable JSON output
--platform string Platform scope for blowhorn profile. One of: bluesky, linkedin, reddit, slack, x, all (all means every platform listed here)
--pace string Accepted by blowhorn profile create because --pace is a global flag, but this command does no paced work -- it sleeps between nothing -- so the value changes nothing about how it runs and appears only in the Pace column of the -v summary. Resolved as CLI flag, then BLOWHORN_PACE, then defaults.pace in .blowhorn.yaml (normal when none is set); an unrecognized value is rejected before anything runs
--risk-profile string Accepted by blowhorn profile create because --risk-profile is a global flag, but this command does no gated work -- no Risk Profile hold, cap or pace applies to it -- so the value changes nothing about how it runs. A value after the command word wins over one before it; an unrecognized value is rejected before anything runs

Also takes the shared flags: --config, --log-dir, --profile, --exclude, --headless, --chrome-launch, --headed, --dry-run, --verbose.

Output: json with --json, text otherwise.

blowhorn profile set

Store KEY=VALUE pairs on a profile: its platform credentials and its run settings. A platform key (LI_*, X_*, RDDT_*, HN_*, SLACK_*, BLUESKY_*, GH_*, YT_*, IG_*, FB_*, TIKTOK_*, slack_workspaces and the <WORKSPACE>SLACK* session keys) is stored in that platform's credential in the store, where runs read it. A run setting (Risk Profile, Risk Profile By Platform, Daily Caps, Quiet Hours, Quiet Hours Time Zone) is stored in the profile's settings in your Blowhorn account, and a value a run could not read is refused. A blank value clears a key. Any other key is refused, and every refusal comes before anything is sent. Nothing is written to a file. The output names the keys that changed and never echoes a value. Replacing a credential an API check judges (GH_TOKEN, the Bluesky handle or app password, a Slack token or captured session) sets that platform back to not checked in profile status until the next check, because each such check records which credential it judged. A browser platform's check is about its saved session and stays.

blowhorn profile status

Report what each profile in your organization is set up for: the platforms it holds an account for (credential key names only -- values are never printed), the browser session directory and its last-modified time, whether another blowhorn process holds its lock, the last recorded session check, and whether the profile is excluded by default. The profiles are your organization's list in your Blowhorn account, read once; a store that cannot be reached is the named cause and exit 3. No browser and no platform network by default: accounts are read from the store's credentials, once for every profile, with the person each profile represents. A credential read the store fails leaves every account unknown and is named on a Credentials: line, not fatal, and a check made then skips every platform and keeps its last results. With --json each platform also carries account_status: the status of the profile's account in your Blowhorn account (connected, disconnected, ...), read once for every profile, or null when none is mapped.

--check-sessions runs a read-only probe per configured platform (LinkedIn, X and Reddit open the saved session in a background window and look for the signed-in page; GitHub, Bluesky and Slack call their APIs) and records the result in the profile's session_status.json under data/cache/profiles/, and records a LinkedIn, X or Reddit sign-in it finds (or one that ended) on the profile's account in your Blowhorn account. It never logs in, never types a credential, and reports busy instead of waiting when a session is in use. --check-platform runs that same probe for one platform only and leaves every other platform's recorded result alone; --check-platform github checks the profile's GitHub token in the store against GitHub (the login it signs in as, its scopes and what they lack) with no browser at all. --roster additionally reads the profiles roster from the store to show which platforms each profile has a handle for; a store that cannot be reached is the named cause and exit 3, and a roster that reads empty or cannot be read is reported on a Roster: line, not fatal. --chrome additionally reads this machine's Chrome profile mappings from the store, once, and Chrome's own profile list, and adds a Chrome column: the mapped Chrome profile directory and whether the name and account recorded when it was mapped still match (drift, missing, unknown). A mapping is identity, never permission. A Chrome profile list that cannot be read is reported on a Chrome: line, not fatal.

Flag Type Default Description
--check-sessions boolean false Probe each configured platform's saved session read-only (in a background browser window unless --headed) and record the result in the profile's session_status.json under data/cache/profiles/; never logs in, and reports busy instead of waiting for a session another blowhorn process is using
--check-platform string Run the --check-sessions probe for this one platform only (implies --check-sessions) and leave the other platforms' recorded results as they are. One of: linkedin, x, reddit, hn, slack, bluesky, github; github, bluesky and slack are API calls and open no browser. Unlike --platform it is never read from BLOWHORN_PLATFORM or defaults.platform, so a default cannot narrow a check nobody asked to narrow

--chrome boolean false Read this machine's Chrome profile mappings from the store and Chrome's profile list, and add a Chrome column: the mapped directory and whether its recorded name and account still match. Opens no browser; a store that cannot be reached is the named cause and exit 3
--json boolean false Emit machine-readable JSON output
--platform string Platform scope for blowhorn profile. One of: bluesky, linkedin, reddit, slack, x, all (all means every platform listed here)
--pace string Pace of the random delays between blowhorn profile status browser steps: a preset name (fast/normal/slow) or a numeric multiplier (e.g. 0.5, 2.0). blowhorn profile update

Replace the fields a person sets on one profile. The profile is named by its name or its id, and the fields come from the JSON document on stdin (--payload-stdin): name (required), description and userId. The document is the whole of them: a description left out is cleared, and a userId left out makes the profile a brand that represents nobody. The profile's run settings (Risk Profile, caps, quiet hours) are read just before the write and sent back as they are, and its owner is unchanged. The same refusals as profile create apply, a rename onto another profile's name included; --dry-run sends nothing.

Argument Required Description
name yes The profile's name, handle-shaped: lowercase letters, digits, - or _, starting with a letter or digit, at most 64 characters, never all, and not a name another visible profile uses. Trimmed and lowercased before it is checked.
Flag Type Default Description
--payload-stdin boolean false Read the profile document (JSON: name, description, userId) from stdin; required
--json boolean false Emit machine-readable JSON output
--platform string Platform scope for blowhorn profile. One of: bluesky, linkedin, reddit, slack, x, all (all means every platform listed here)
--pace string Accepted by blowhorn profile update because --pace is a global flag, but this command does no paced work -- it sleeps between nothing -- so the value changes nothing about how it runs and appears only in the Pace column of the -v summary. Resolved as CLI flag, then BLOWHORN_PACE, then defaults.pace in .blowhorn.yaml (normal when none is set); an unrecognized value is rejected before anything runs
--risk-profile string Accepted by blowhorn profile update because --risk-profile is a global flag, but this command does no gated work -- no Risk Profile hold, cap or pace applies to it -- so the value changes nothing about how it runs. A value after the command word wins over one before it; an unrecognized value is rejected before anything runs

Also takes the shared flags: --config, --log-dir, --profile, --exclude, --headless, --chrome-launch, --headed, --dry-run, --verbose.
